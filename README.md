# DuoBlur

> 戴上 AirPods，转头时屏幕内容按折叠屏的"折页"方式从一侧卷起模糊，转回正视恢复清晰。

一个 macOS 菜单栏常驻应用。读取 AirPods 的头部姿态，把头的左右转动映射为"折叠量"，
用 Metal 渲染一层覆盖全屏的渐进模糊。

技术栈：Swift 6 + SwiftPM + AppKit/SwiftUI + Metal + ScreenCaptureKit + CoreMotion。
**零第三方依赖，零网络访问。**

---

## 效果

- **正视屏幕** —— 屏幕完全清晰。覆盖层在无效果时直接隐藏，因此正视状态下没有额外延迟。
- **头转向一侧** —— 屏幕从背离视线的那一侧开始模糊，像折叠屏面板被卷起；随转动角度向另一侧蔓延，
  折痕高光跟着转头移动。
- **转回正视** —— 反向解析回清晰。

模糊不是盖一层均匀高斯。折痕位置、渐进曲线、折痕亮线、镜面掠射光、掠射变暗都随折叠量联动，
整条曲线的参数集中在 `FoldParameters` 里，着色器不硬编码任何常数。四个预设见下方。

## 这不是什么

- **不是安全产品。** 不提供任何防窥或防截屏保护，它只是一段视觉交互效果。
  请不要在公共场合依赖它保护敏感信息。
- **不是屏幕录制工具。** 捕获的帧只存在于内存与 GPU 纹理中，处理完即丢：不落盘、不联网、不上传。
  锁屏与休眠时完全停止捕获。
- 不注入、不 hook 任何其他进程，不使用私有 API。

## 系统要求

- macOS 14.0+（`CMHeadphoneMotionManager` 的下限）
- 一副支持动态头部追踪的耳机，即带 IMU 的型号：

| | 型号 |
|---|---|
| 可用 | AirPods Pro 1 / 2 / 3、AirPods Max、AirPods 3 / 4、Beats Fit Pro、Beats Studio Pro |
| 不可用 | AirPods 2 及更早（无 IMU 数据） |

耳机需要是这台 Mac 当前的音频输出设备，头部追踪数据才会推流。

## 权限

| 权限 | 用途 | 拒绝后 |
|---|---|---|
| 屏幕录制 | 读取屏幕内容并重新绘制为折页模糊 | 降级为"仅变暗"模式 |
| 运动与健身 | 读取 AirPods 头部姿态 | 效果不可用，只剩调试模式 |

不需要辅助功能、输入监控、摄像头、麦克风、网络。

捕获时会**排除自身进程**，所以覆盖窗不会被自己捕获，不存在镜像反馈回路。

## 构建

```bash
make app     # 构建 + 打包 + 签名 → build/DuoBlur.app
make run     # 构建并启动
make test    # 单元测试与属性测试
make icon    # 生成应用图标
make clean
```

`make run` 会经 LaunchServices 启动。直接跑 `.build/` 里的裸二进制不会触发系统权限弹窗，
所以别绕过 `open`。

## 使用

启动后应用常驻菜单栏（不显示 Dock 图标）。菜单项：

| 菜单项 | 作用 |
|---|---|
| 开始（监听 + 屏幕效果） | 建立屏幕捕获并开始读头部姿态 |
| 把当前姿态设为正中 | 把当前头部朝向重新锚定为"正视"，用于坐姿偏移后的回中 |
| 打开控制面板… | 打开探针窗口：实时数值、参数滑杆、调试模式、实测记录导出 |
| 打开「运动与健身」设置… | 跳到系统设置对应页面 |
| 打开「屏幕录制」设置… | 同上 |

### 首次运行需要授权（只一次）

1. 系统设置 → 隐私与安全性 → **录屏与系统录音** → 打开 **DuoBlur**
2. 系统设置 → 隐私与安全性 → **运动与健身** → 打开 **DuoBlur**
3. **退出并重启 DuoBlur**（macOS 要求屏幕录制权限变更后重启才生效）
4. 控制面板里点「开始」→ 看到真实屏幕的折页模糊，同时开始读头部姿态

> macOS 15+ 起，屏幕录制权限**只能在系统设置里手动打开**，被拒绝后不会再弹窗。

用 `make reset-tcc` 可以重置本应用的授权，重新走一遍首次启动流程。

### 不需要任何权限就能看到效果

着色器可以自己生成测试图案（含 1px 细网格、灰阶渐变、彩块），再做折页模糊。
所以**不授予屏幕录制权限**也能验证效果与调参。在控制面板里把「调试模式」切到「合成测试图案」，
或直接用命令行：

```bash
make app
open build/DuoBlur.app --args --effect --debug-mode pattern --amount 0.45 --side right --exit-after 20
```

### 调试模式

| 模式 | 用途 |
|---|---|
| 正常 | 读取真实屏幕并生成折页模糊（需要屏幕录制权限） |
| 直通自检 | 原样贴回捕获内容 + 边框标记。确认覆盖层在最上层、几何对齐、没有自我捕获的反馈回路 |
| 合成测试图案 | 不读屏幕，自己生成图案。免权限验证效果与调参 |
| 通道可视化 | 把内部的 t / 变暗系数 / 模糊半径画成 RGB，用于像素级核对 |

### 命令行参数

适合自动验证与演示。**演示给别人时记得带 `--exit-after`**，免得在对方机器上留下一层覆盖窗。

| 参数 | 含义 |
|---|---|
| `--effect` | 启动即启用屏幕效果，且不自动打开探针窗口 |
| `--debug-mode <off\|passthrough\|pattern\|channels>` | 调试模式 |
| `--amount <0..1>` | 固定折叠量，不跟随头部 |
| `--side <left\|right>` | 铰链在哪一侧 |
| `--preset <duoSweep\|duoClassic\|frost\|cinematic>` | 使用某个预设 |
| `--auto-drive` | 改为跟随真实头部数据（默认固定在 `--amount`） |
| `--exit-after <秒>` | 若干秒后自动退出 |
| `--log-file <路径>` | 把事件日志写到文件 |
| `--capture-frame <路径>` | 把当前参数下的一帧离屏渲染成 PNG，用于定量核对着色器输出 |
| `--keep-probe` | 启用效果时也保留探针窗口 |

## 效果预设

| 预设 | 空间分布 | 观感 |
|---|---|---|
| `duoSweep`（默认） | sweep | 折痕随转头在屏幕上移动，模糊从自由边长出 |
| `duoClassic` | ramp | 整屏当作一块折叠面板，铰链处始终清晰 |
| `frost` | uniform | 整屏均匀磨砂 + 轻微变暗，最"磨砂玻璃"的一档 |
| `cinematic` | sweep | 更重：始终带一层薄雾，高光更强 |

三档响应度（稳 / 平衡 / 灵敏）会联动调整 One Euro 滤波器与弹簧的参数，
是在"抖动"与"延迟"之间做取舍的单一开关。除此之外的每个参数都能在控制面板里单独调，
并显示对应的等效折叠角（176° = 完全平展，20° ≈ 闭合）。

```

                   阻尼弹簧、转向映射、折叠参数与预设。可 100% 单测。

                   硬件经 MotionSource 协议隔离在边界之外。

                   折页着色器、每屏一个 CADisplayLink 的渲染协调器。
  DuoBlurApp/      菜单栏入口、运动探针/控制面板、权限与启动参数。
Resources/         Info.plist、entitlements、图标生成脚本。
Tests/             DuoBlurCore 与 DuoBlurMotion 的单元与属性测试。
```

## 实现要点

**姿态读取。** CoreMotion 的头部姿态参考系是数据流启动时任意捕获的，启动时并不为零，
所以第一个样本会被取为新基线，之后都相对它计算。这一步不能省，否则一启动屏幕就是糊的。
原始姿态与处理后姿态都会保留，控制面板可以一键复制完整实测记录用于排查方向或量级。

**数据流的坑。** 首个样本的延迟是 0.25s 到 10s+ 的不确定值；回调可能带 `nil` 并有 error；
自动入耳检测关闭时会静默断流；还会遇到"系统报告已连接但采样率恒为 0"的卡死——
这种情况 `CMHeadphoneMotionManager` 无法复活，只能整个重建实例。这些都在
`HeadphoneMotionSource` 里集中处理，配合一个不依赖事件的陈旧看门狗。

**捕获管线。** 每块显示器一路 `SCStream`。`SCStream` 是内容变化驱动的，屏幕上没有变化就不推帧，
所以建流后会主动抓一帧打底。建流链路上任何一步都可能"无错误、无帧、无解释"地挂住，
因此每一步都包了超时并明确指出卡在哪一步。几何信息从帧附件读取而不是假设 1:1 对齐，
`DisplayGeometry` 负责把捕获画面仿射映射到屏幕坐标。

**渲染。** 模糊用 3×3 二项式预过滤 + mipmap 链近似大半径高斯，比逐像素采样快得多。
折痕线与镜面光以"离铰链的距离"表达（屏幕空间比例），而不是面板内进度，
否则低折叠量时高光带会被拉宽、峰值被稀释到看不见。

**性能。** 折叠量为零时完全跳过着色器编码；覆盖层隐藏时捕获仍在跑但不合成。
为正视状态省掉一切不必要的 GPU 工作，是这个效果能不能日常开着用的关键。

## 开发

`make app` 会用一个自签名证书签名（默认 `DuoBlur Dev`，可用 `Makefile.local` 覆盖 `SIGN_ID`）。
这不只是为了本地跑得起来：adhoc 签名（`codesign --sign -`）的身份每次重建都会变，
于是**屏幕录制与运动健身授权每次重新构建后都要重新给**。

一次性创建自签名证书即可解决：

1. 钥匙串访问 → 证书助理 → 创建证书…
2. 名称 `DuoBlur Dev`，身份类型「自签名根证书」，证书类型「代码签名」，3650 天
3. 重跑 `make app`，输出会显示"已用 DuoBlur Dev 签名 —— TCC 授权可跨重建保持"

找不到证书时会自动退回 adhoc 并打印警告。证书是本地自签名的，处于未受信任状态属正常，
不影响 `codesign` 使用它，也不影响授权的稳定性。
